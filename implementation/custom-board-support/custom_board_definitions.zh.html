6.6.9. 自定义板级定义格式¶

自定义板级定义文件在 motorBench® Development Suite 中遵循规定格式。它们可读且可手动编辑，但基于定义的数据结构，组织为数据模型。

  • 数据模型必须符合 板级定义 schema

  • 数据模型 被序列化为文本格式 （motorBench 2.50 中为 YAML）

以下章节描述这些约束。

6.6.9.1. 使用序列化数据模型¶

6.6.9.1.1. 简介¶

术语数据模型指用于建模系统的任何层次树结构。在 motorBench® Development Suite 中，我们使用多个数据模型，用于 代码生成， 参数定制 和 自定义板级支持。

某些数据模型可以序列化为文本格式，如 JSON， YAML，以及 TOML，这便于在适当情况下使用版本控制和手动编辑。motorBench® Development Suite 2.50 的自定义板功能支持导入 YAML 格式的文件。

motorBench 中板级定义的数据模型

  • 可序列化为 JSON 并可从 JSON 反序列化，支持以下值类型

    • 数字

    • 字符串

    • 布尔值（true 和 false）

    • null

    • 值列表（= 数组/有序序列）

    • 值映射（= 字典/无序键值对集合）

  • 通常以 YAML 格式描述（比 JSON 更易读写）

  • 通过以点分隔的路径引用，例如 characteristics.current.phase.fullscale

6.6.9.1.2. YAML 示例¶

以下是 YAML 格式的部分板级定义摘录。其层次结构通过缩进层级表达。

注

编辑时，建议使用支持 YAML 的编辑器，如 VSCode 或 Notepad++，具备语法高亮和展开/折叠层次结构部分的功能。

警告

为避免对齐不当和不兼容，请使用空格而非制表符进行缩进。

代码清单 6.3  ¶
 identification：
   id： custom_board
   displayName： "Custom Board"
   description： "Custom Board"
 characteristics：
   device： dsPIC33CK256MP508
   # 这是一个注释
   current：
     phase：
       fullscale： 21.8
       maximum：
         # WOO HOO HOO
         continuous： 14.1
       timeConstant： 184.0e-9
     dcLink：
       fullscale： 21.8
       timeConstant： 184.0e-9
 peripherals：
   adc：
     current：
       a：
         channel： AN0
         inverted： true
         signed： true
       b：
         channel： AN1
         inverted： true
         signed： true
   opamp：
     enabled：
     - 1
     - 2
     - 3

  • 注释 表示为 # 后跟任意文本，该文本将被忽略至行尾

  • 数字 表示为整数、浮点值或科学记数法

    • 浮点值 可以表示为小数（示例： 0.38， 8702.1）或科学记数法（示例： -3.02e-5， 4.73e3）。

      注

      使用科学记数法时，请确保在指数前使用小数点，例如 3.0e-5 而非 3e-5。这可避免某些软件库中的问题。

  • Booleans 表示为固定文本 true 和 false （注：内容区分大小写）

  • Null 值表示为固定文本 null

  • 字符串 表示为非数字、非布尔值、非 null 的文本。

    • 为安全起见，在 YAML 中使用引号分隔字符串；YAML 包含其他令人困惑的表示方式，如 on 和 off （用于布尔值）或 12:00 这是一个时间值。

    • YAML 中还有其他几种表达多行字符串的方式；板级定义文件中不需要也不应使用它们。

  • 列表 是缩进值的有序序列，每个值前以连字符开头（末尾 opamp.enabled）

    • 列表也可以用替代的紧凑语法表示 [value1, value2, value3] 如 Javascript 和 Python 中所示，但我们通常不在示例中使用。

  • 映射 是缩进键/值对的无序序列，其中键为字符串，后跟冒号，再跟一个与冒号以空格或换行符分隔的值。

    • 上面的示例文档是一个包含三个键的映射， identification， characteristics，以及 peripherals。

    • 与 identification 键关联的值本身是一个包含三个键的映射： id， displayName，以及 description。这些键各自引用紧随键后（空格之后）的字符串值。

    • 映射也可以用 Javascript 中的替代紧凑语法表示，但我们通常不在示例中使用：

      {key1： value1， key2： value2， key3： value3}

    • 映射中元素的顺序不重要，可以排列而不改变值，即使生成的序列化 YAML 文件不同。

  • 数据模型中的值可以通过 路径引用，它是一个使用句点/点 。 来表示按键索引映射，使用方括号 [] 来表示按整数值索引列表。在上面的示例数据模型中：

    • 路径 identification.id 引用字符串 custom_board

    • 路径 peripherals.opamp.enabled[1] 引用数字 2

    • 路径 peripherals.adc.current.a 引用以下映射：

      channel： AN0
inverted： true
signed： true

有关 YAML 的更详细介绍，有各种公开资源；以下似乎是较为易读的教程：

  • Dojo Five YAML Tutorial: How To’s, Best Practices & Getting Started

6.6.9.2. 自定义板级 schema¶

自定义板级定义中的数据模型是符合下表所列 schema 的层次树结构，组织在三个顶层节下：

  • identification — 涵盖与板名称和描述相关的数据

  • characteristics — 涵盖与板相关的参数，如最大 PWM 频率、满量程 DC 母线电压、最大连续相电流等

  • peripherals — 涵盖外设配置选择，如 UART 引脚分配、ADC 通道映射、PWM 故障源和极性等

表格的每一行描述树中的一个条目，具有以下属性：

  • 一个类型，可以是 标准数据模型类型 之一，或以下之一：

    • 命名类型，如 [digitalPolarity]，具有约束结构。这些类型列在表格末尾。

    • 一个 enum，即从若干固定选项中选择（这些在描述中列出）

    • 约束数值范围，此处以不等式表示为 \(n\) or \(x\)：

      • \(n\)：整数范围，例如 \(1 \le n \le 3\)

      • \(x\)：浮点范围，例如 \(0.0 \le x \le 1.0\) or \(x \ge 0.0\)

  • 单位（如适用）——例如 V（伏特）或 A（安培）或 s（秒）

  • 该条目是否为必填（Req'd，以绿色勾号 ）或可选

    注

    条目在其父条目的上下文中为必填或可选。例如， peripherals.qei 是可选的，但如果存在，则 peripherals.qei.pins 为必填。
