6.7. 资源占用¶

本节提供资源占用的参考数据，涵盖程序存储器、数据存储器和 CPU 使用率。

请注意：资源占用取决于多种因素，可能与以下所示数据不同。这些因素包括：

  • 编译器版本

  • 编译器优化级别

  • 编译器标志

  • motorBench® Development Suite 中的设置

  • MCC 中的设置

  • MCAF 参数值

6.7.1. 测试用例¶

在以下描述的每种情况下，MCAF 固件包使用默认设置并选择 AN1292 PLL 估计器，使用 Nidec Hurst DMA0204024B101 电机和 dsPICDEM® MCLV-2 开发板。源代码使用 XC16 和 XC-DSC 以 -O1 和 -O2 编译级别为器件 dsPIC33EP256MC506、dsPIC33CK256MP508 和 dsPIC33CK64MC105 构建。宏 MCAF_TEST_PROFILING 和 MCAF_TEST_HARNESS 在 options.h 中启用（见 性能分析时间戳）。

6.7.1.1. 程序和数据存储器¶

程序和数据存储器的资源占用统计数据来自 map 文件。

6.7.1.2. CPU 使用率¶

CPU 使用率通过修改后的 MCAF 变体确定，这些变体在电机控制 ISR 的多个点通过 UART 传输 CPU 周期计数数据，针对 20 kHz PWM ISR，使用以 100 MIPS 运行的 dsPIC33CK256MP508 和 dsPIC33CK64MC105，以及以 70 MIPS 运行的 dsPIC33EP256MC506。

CPU 周期计数在约 4 秒内测量，电机经历启动、运行和减速停止。电机控制 ISR 内的时间从低到高排序，计算最坏情况和 99.9% 百分位。例如，20 kHz 下 4 秒的数据代表 80,000 个数据点，因此 99.9% 百分位代表 CPU 使用率第 80 高的样本。这代表了用于估计随时间累积剩余 CPU 容量的保守估计，并排除了长执行路径在同一 ISR 周期中巧合时可能出现的时序尖峰。最坏情况 CPU 使用率应用于确定 ISR 不超过可用 CPU 时间。CPU 时间的变化由多种因素引起，包括：

  • 分支（if 语句）可能采取不同且不等长的执行路径

  • 某些算法以 ISR 的约数频率运行，例如 PLL 位置估计器有一部分代码每 8 个 ISR 周期运行一次

  • 在 状态机的不同状态期间，代码的不同部分被启用或禁用

主循环 CPU 使用率未进行性能分析但很小（估计 < 0.1 MIPS）；主循环中运行的代码不多。

6.7.9. MCAF 版本间的变化¶

MCAF R3 和 R4 之间 ISR 使用率的表观下降不应被视为结论性的。Microchip 工作人员进行了类似测试，其中 CPU 使用时间从 MCAF R3 到 R4 略有增加；我们已意识到此问题，正在研究在受控条件下比较 MCAF 版本间 CPU 使用率的更可靠方法。

与 MCAF R5 相比，MCAF R6 和 R7 的 CPU 使用率均略有增加。

与 MCAF R7 相比，MCAF R8 的 CPU 使用率略有增加。

Microchip 工作人员正在研究在未来 MCAF 版本中减少 CPU 使用率增加的潜在方法。
