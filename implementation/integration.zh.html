6.5. 与自定义代码的集成¶

6.5.1. 概述¶

电机控制应用框架及附带的 示例应用 设计为使 motorBench® Development Suite 生成的代码可在以下开发板上作为演示项目直接使用，无需修改：

  • dsPICDEM® MCLV-2 开发板

  • dsPICDEM® MCHV-2 开发板

  • dsPICDEM® MCHV-3 开发板

  • dsPIC33CK 低压电机控制 (LVMC) 开发板

  • MCS MCLV-48V-300W 开发板

  • MCHV-230VAC-1.5kW 电机控制高压开发板

在其他项目中使用 MCAF 通常需要手动将示例应用替换为自定义应用。虽然 MCAPI 允许自定义应用在无需了解 MCAF 各组件和模块的情况下控制电机并获取反馈，但此工作仍要求应用开发者了解 MCAF 的时序和资源需求。参见 调度与优化 和 资源使用 以获取更多信息。

注

除 mcapi.h 和 mcapi_types.h 中的现有接口外，MCAF 中的函数、模块和组件仍可能变更，截至 MCAF R7，MCAF 内部没有任何接口已被冻结。因此，不建议自定义应用在不使用 MCAPI。

最后：如果与自定义代码的集成对您很重要，我们鼓励您提供反馈以指导该领域的未来开发。请 联系 Microchip 提出任何意见或建议。

6.5.2. 修改主应用¶

主应用包含一个 示例应用 于 mcaf_sample_application.c 中，使用 运动控制 API (MCAPI)实现控制电机的简单用户界面。示例应用的所有接口名称均以 APP_ 前缀开头。此示例应用可被修改或替换为自定义代码。

MCAF 与修改后的主应用正常工作的要求如下：

  • MCAF_MainInit() 应在系统启动时在 SYSTEM_Initialize()

  • MCAF_MainLoop() 之后调用。应在主循环的每次迭代中调用。此函数不必周期性执行，但最小重复频率应约为 100Hz 以服务各项功能。

  • 板级处理函数， MCAF_BoardServiceTasks()应按 UI 服务周期 （在 motorBench® Development Suite 的 Customize 页面中定义）的频率周期性调用。例如，此函数可从应用定时器 ISR 或调度器中调用。

自定义应用与 MCAF 接口的要求如下：

  • 应设置应用初始化函数以初始化指向 MCAF 中 MCAPI_MOTOR_DATA 和 MCAF_BOARD_DATA 数据的指针。参见 APP_ApplicationInitialize() 中的示例。

  • 应用初始化函数应从 MCAF_MainInit() 中调用以初始化应用-MCAF 接口。

  • 应用应使用 MCAPI 在运行时与 MCAF 交互。

6.5.3. 修改 FOC 模块¶

由于 MCAF 中状态机、 FOC和监督算法之间仍存在紧密耦合，不建议修改 FOC 模块。这包括对无传感器估计器、PI 控制器或 磁通控制模块。

6.5.4. 修改状态机¶

由于 MCAF R7 中状态机、 FOC和监督算法之间仍存在紧密耦合，不建议修改状态机。

6.5.5. 修改监督算法¶

监督算法（看门狗管理除外）在 MCAF R7 之后的后续版本中可能变更。因此，不建议修改此模块。

看门狗管理涉及 MCAF 的多个方面；要更改此行为，请参见 看门狗管理 和/或在代码中搜索 watchdog；相关部分位于 traps， ui， isr和 main 模块。
