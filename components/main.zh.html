4.1. 主应用程序¶

如 调度一节中所述，主应用程序由一部分在 main()。

4.1.1. 实现说明¶

4.1.1.1. MCAF R1 – R5¶

在 MCAF R6 之前，主应用程序与 MCAF 紧密集成，同时将用户界面的职责完全交由 外部接口 组件定义和实现。

4.1.1.2. MCAF R6¶

主应用程序已被重写以包含一个示例应用程序。示例应用程序通过 运动控制 API（MCAPI） 与 MCAF 交互，以控制电机并获取反馈。

4.1.1.3. MCAF R7¶

主应用程序现在使用 运动控制 API 作为与 MCAF 接口的唯一入口，减少了对 MCAF 内部的暴露。

  • 示例应用程序可以在电机停止过程中尝试重新启动电机

  • 新增了两个文件：mcaf_main.c 和 mcaf_sample_application.h

  • 将 MCAF_MOTOR_DATA motor 和 MCAF_SYSTEM_DATA systemData 的定义从

    sample_mcaf_application.c 到 mcaf_main.c

  • 更新了 APP_ApplicationInitialize() 和 APP_ApplicationStep() 的函数签名，以包含指向 MCAPI 数据结构的指针。

  • 将 MCAF_Init() 和 MCAF_MainLoop() 移至 mcaf_main.c

4.1.1.3.1. 示例应用程序¶

示例应用程序的用户界面行为可概括如下：

  • 如果电机正在停止/已停止，则主按键启动电机。如果在 STOPPING 状态下按下主按键， 状态机 将根据 停止模式：

    • 最小影响 PWM 状态转换序列： STOPPING， STOPPED， STARTING， RUNNING

    • 闭环（电流或速度） 状态转换序列： STOPPING， RUNNING

  • 如果电机正在启动/运行，则主按键停止电机。

  • 如果电机处于故障状态，则主按键清除所有待处理的故障。

  • 如果 MCAF 处于其某种测试模式，则主按键和副按键不起任何作用。

  • 副按键改变旋转方向。

  • 电位器为电机设定速度参考值，其最小和最大限值由 MCAF 定义并通过 MCAPI 函数 MCAPI_VelocityReferenceMinimumGet() 和 MCAPI_VelocityReferenceMaximumGet() 提供。

  • 在示例应用程序中，可以通过清除 hardwareUiEnabled 来禁用按键和电位器用户界面，例如使用实时诊断工具 X2Cscope。

有关按键用户界面的实现细节，请参见 外部接口 。

LED 的用户界面由 外部接口 组件定义和实现。

4.1.1.4.1. 陷阱处理模块¶

dsPIC® DSC 器件中的硬件陷阱向量包含针对堆栈溢出或地址对齐错误等事件的处理程序。在 MCAF 中，这些位于 traps 模块中。正常的处理逻辑是通过调用 halt_on_error() 函数来发出不可恢复错误的信号，该函数记录错误代码并进入无限循环，通过 MCAF_UiFlashErrorCodeForever() 闪烁 LED 来指示错误代码，如 UI 模块中所述。

此行为有两个小的偏差：

  • DMA 写冲突：当 CPU 和 DMA 通道写入同一地址时发生（此时 CPU “获胜”，DMA 写入被忽略）。在本应用程序中，此情况不视为错误，仅在使用 DMA 读写 UART 的诊断模块的某个变体中偶尔出现。DMA 陷阱处理程序会递增一个计数器，用于评估 DMA 写冲突的频率。

  • 堆栈溢出：堆栈溢出是一种不可恢复的错误，但略有不同，因为堆栈指针（dsPIC® DSC 器件上的 W15）可能无效。在这种情况下，MCAF 会格外小心地使用一个小的“故障安全堆栈”，这是一个为此情况预留的静态内存区域，其大小足以满足 MCAF_UiFlashErrorCodeForever() 函数的堆栈需求。

除了硬件陷阱外， traps 模块还包含检查复位原因的逻辑，以便在看门狗复位时，可以通过 MCAF_UiFlashErrorCodeForever()。
