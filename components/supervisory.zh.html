4.6. 监控算法¶

监控算法包括：

  • 监控（包括故障检测）

    • 过压/欠压检测

    • 过流检测

    • 过温检测

    • 看门狗定时器管理

    • 堵转检测和恢复

  • 其他监控算法

    • 热管理

    • 饱和和反饱和管理（如果速度和电流控制器中尚未包含）

    • 自适应估计器（例如在线电阻估计）

    • 弱磁控制

    • 最大转矩每安培（MTPA）控制器

4.6.1. 实现说明¶

4.6.1.1. 堵转检测¶

堵转检测由五种方法组成，用于检测过载或堵转的电机：

  • 速度不足 ——如果电机速度估计器保持准确，当速度估计的幅值降至阈值以下时，可以检测到电机堵转。

  • 方差 ——如果无传感器角度估计器与电机反电动势失去同步，电机将趋于堵转，但无传感器估计器可能继续估计非零电气频率。在这种情况下，电压和电流在估计的电气频率处表现出振荡。方差检测试图识别电压和电流振荡。

  • 负 Ed ——负 d 轴估计反电动势（\(E_d\)）的尖峰可能在电机堵转且无传感器角度估计器失去同步时出现。这可以用作检测方法。

  • 转矩角 ——估计反电动势与电机端电压之间的角度随电机负载增加或堵转而增大。这在数学上等价于反电动势幅值与端电压的比值降至低于速度相关阈值。

  • 软件过流 ——重载电机可能超过可接受的定子电流水平。

不同电机呈现不同的堵转症状，由上述不同算法检测。所有算法都有某种滤波器或延迟以避免过早或误检测。（见 勘误）

更具体的信息可在 监控 （包括堵转检测）和 恢复 的相关文档中找到。

4.6.1.2. 过温检测¶

MCAF 为 提供桥臂温度测量的电路板提供过温检测故障，在 MCAF R7 中添加。

如果 滤波后的桥臂温度 超过指定阈值，则触发故障。这提供了一定的抗噪声能力，以避免原始温度信号中的尖峰影响。

4.6.1.3. 其他算法¶

MCAF R1 – R5 不包含以下任何算法：

  • 弱磁控制

  • 热管理

  • 自适应估计器

  • MTPA

4.6.1.4. 看门狗定时器管理¶

该 watchdog 模块利用了 PIC® 微控制器和 dsPIC® DSC 器件中的看门狗定时器。硬件看门狗超时相对简单，只是一个自动递增的计数器，溢出时会导致看门狗复位；固件通过清除看门狗定时器作为其正常运行的信号来防止这种情况，因此如果阻塞操作意外地使固件停止响应，将发生复位。

MCAF 使用硬件看门狗定时器来捕获 中 主循环和控制 ISR的不响应代码。它通过要求运行两个简单任务来实现，一个在主循环中，另一个在控制 ISR中，以便看门狗定时器被复位。函数 MCAF_WatchdogManageIsr() 是在控制 ISR中实际清除看门狗定时器的任务，但它还维护一个“软件看门狗”计数器 isrCount ，在每次控制环路更新时递增。主循环任务有责任调用 MCAF_WatchdogManageMainLoop()，该函数清除软件计数器，频率要足够高以使软件看门狗不会达到超时。

  • 如果 ISR 变得不响应，它将不会清除硬件看门狗定时器，在下一次看门狗超时时，将发生看门狗复位。

  • 如果主循环变得不响应，它将不会清除软件看门狗定时器，当该定时器达到超时阈值时， ISR 将停止清除硬件看门狗定时器。在下一次看门狗超时时，将发生看门狗复位。主循环软件看门狗超时本质上比硬件看门狗超时长得多，但它也是一个不太关键的任务线程。

看门狗复位的原因可以通过检查软件看门狗计数器的值来确定；如果它高于超时阈值，则主循环不响应；如果软件计数器低于超时阈值，则控制 ISR 不响应。

4.6.1.5. 故障清除逻辑¶

该 MCAPI 在 MCAF 中的各种故障处理过程调用 handleFaultFlags() 函数时实现故障清除逻辑。故障清除逻辑的目的是通过捕获故障信息、分析特定故障条件并执行适当的恢复操作来维持系统稳定性和安全性。

4.6.1.5.1. MCAF 中检测到的故障¶

MCAF 中的故障标志映射到 MCAPI 中的相应故障标志，如 API 描述中的 MCAPI 故障标志表所述。例如， MCAF_GATE_DRIVER_FAULT_DETECT 映射到 MCAPI_FAULT_FLAG_GATE_DRIVER。

这些故障根据检测来源分类：

  • MCAF 固件检测到的故障

    • MCAF_OVERVOLTAGE_FAULT_DETECT

    • MCAF_UNDERVOLTAGE_FAULT_DETECT

    • MCAF_OVERTEMPERATURE_FAULT_DETECT

  • 外部硬件检测到的故障

    • MCAF_OVERCURRENT_HW_FAULT_DETECT

    • MCAF_GATE_DRIVER_FAULT_DETECT

该 MCAPI_FAULT_FLAG_MOTOR_DRIVE 故障在 MCAPI 中定义为通用标志，用于表示所有未显式映射的 MCAF 故障。

该 MCAPI_FAULT_FLAG_OVERCURRENT 用于报告过流条件，如果硬件配置共享过流和过压检测的硬件故障源，则也会报告过压。

每种硬件组合都有自己配置的故障源引脚。（见 自定义电路板格式。）

4.6.1.5.2. 清除 MCAF 固件级故障¶

大多数 MCAF 固件级故障在当前 ISR 周期内通过以下序列清除：

  • 如果相应的故障清除标志已设置，MCAPI 清除故障标志。

  • MCAPI 从 MCAF 读取活动故障状态。

  • 如果没有剩余的活动故障，MCAPI 请求 MCAF 退出故障状态。

4.6.1.5.3. 清除硬件级故障¶

某些硬件级故障需要多个 ISR 周期才能清除，必须与固件级故障不同地处理。

  • MCAPI_FAULT_FLAG_OVERCURRENT ——由于 PWM 故障锁定，至少需要两个 ISR 周期才能清除此故障。 fault_handle 模块与 MCAF 交互以清除故障。

  • MCAPI_FAULT_FLAG_GATE_DRIVER ——执行电源循环是目前清除此故障的唯一可用方法。（见 勘误）

4.6.1.5.4. 无 PWM 故障输入的自定义电路板¶

MCAF 支持使用硬件 PWM 故障信号以处理器无关的方式检测过压或过流条件。通过在电路板定义中指定此故障源——作为指定引脚上的输入或片上比较器的输出——MCAF 可以配置 dsPIC® DSC 上的 PWM 发生器来监控此输入，并在发生硬件故障时自动禁用 PWM 输出。

对于不包含此类故障信号的自定义电路板，故障源可以设置为 无，从而禁用基于硬件的故障检测。在这种配置下， MCAF_OVERCURRENT_HW_FAULT_DETECT 不会被触发。

警告

不建议设计没有硬件 PWM 故障信号的电机控制电路板。这是一项关键功能，有助于检测故障并防止故障传播。

4.6.1.5.5. 与 MCAPI 的交互¶

应用程序可以查询和清除 MCAPI 故障标志：

  • MCAPI_FaultStatusGet() 返回电机的当前故障位域。

  • MCAPI_FaultStatusClear() 请求通过掩码清除选定的故障标志（清除不会重启电机）。

典型序列是使用 MCAPI_FaultStatusGet()读取故障标志，调用 MCAPI_FaultStatusClear() 清除所需位，然后重新读取直到这些位清除。MCAPI 函数的延迟限制没有严格界定，但故障状态读取/清除请求通常在 2 个 ISR 周期内生效。 MCAPI_FAULT_FLAG_OVERCURRENT 由于 清除 MCAF 固件级故障。

4.6.1.6. 监控勘误¶

  • 堵转检测的转矩角检测方法难以自动调优。它对某些电机效果良好，但对其他电机可能导致误检测故障。自 MCAF R3 起，我们默认禁用了此检测方法。可以通过更改 MCAF_StallDetectInit() 来重新启用，将堵转检测标志掩码初始化如下：

    pstallDetect->stallDetectFlagMask = MCAF_ALL_STALL_DETECT_METHODS_ENABLED；

  • MCAPI 不会清除 MCAPI_FAULT_FLAG_GATE_DRIVER 故障，因为栅极驱动器故障锁定。（DB_MC-5666；适用性：R8）
