4.9. 硬件抽象层（HAL）¶

HAL 被 MCAF 用于通过众所周知的函数调用来解耦所有设备特定硬件寄存器的知识。HAL 由两层组成： MPLAB® 代码配置器 （MCC）层和 HAF 层。MCC 层是基础层，其中设备特定的硬件寄存器被抽象为一系列外设驱动 API。然后 HAF 层调用 MCC 层中的函数来抽象设备特定功能，使更高层的 MCAF 层与设备无关。

只要保留 HAL 函数名称和语义，HAL 组件就可以被替换为替代实现。

4.9.1. 硬件相关行为¶

MCAF 的某些方面利用 HAL 提供的功能，但行为的选择在于 MCAF。其中一些选择是为了便于在具有不同底层外设机制的设备之间移植。

注意：这种可移植性是有代价的 ——每个系列的微控制器都有某些最优的外设使用模式，但这些模式可能无法很好地跨不同系列使用。

对于 CPU 或外设性能是严重约束且优先于可移植性和可维护性的客户，应考虑根据需要修改 HAL 以满足这些约束。Microchip 不推荐这种方法，除非绝对必要。

4.9.1.1. 中断优先级¶

MCAF 的大部分代码在几个不同的中断服务程序中执行。以下中断按从高到低的优先级列出，供 MCAF 使用。参见 调度要求 一节了解更多信息。

  • 主 ADC ISR——执行 状态机 和几个其他关键 MCAF 组件，每个 PWM 周期执行一次。

  • 单通道 ADC ISR——每个 PWM 周期对直流母线电流采样两次。仅在 单通道电流测量 时执行。

  • 定时器 ISR——执行 板级服务 任务和 主应用程序 周期性地。

4.9.1.2. PWM 输出¶

PWM 三相桥的输出设置为以下三种模式之一：

  • 关闭 ——在设备复位时和严重故障期间，桥完全关闭

  • “最小影响” ——当不对电机端子施加电压时（在 状态机的某些状态下），上桥臂晶体管完全关闭，但下桥臂晶体管以低占空比（通常 1-3%）导通，以维持自举栅极驱动电容器的电荷。参见 MCAF_SetPwmMinimalImpact() 在 state_machine 模块中。

  • 正常 ——当对电机端子施加电压时，所有 6 个晶体管都在开关，分为三对互补对，每相一对。每相在一个晶体管关断和互补晶体管导通之间有死区时间，以避免直通。

4.9.1.3. 过流故障检测与清除¶

MCAF 需要两阶段故障清除方案来复位锁存电路。为了在 dsPIC33EP 设备的锁存模式下清除故障，需要在下一个 PWM 周期清除中断标志并启用故障模式。请参阅 DS70645C p.14-101 获取更多信息。

阶段 1 在当前 PWM 周期发生

  • 33EP：禁用故障锁存模式

  • 33CK：清除故障锁存

阶段 2 在下一个 PWM 周期发生

  • 33CK 和 33EP：清除故障中断标志

  • 33EP：启用故障锁存

4.9.1.4.1. 33EP 和 33CK PWM 模块之间的差异及其对 ADC 操作的影响¶

为了准确测量电机相电流，ADC 必须在低侧占空比脉冲的中间开始采样。这是为了在低侧脉冲结束前留出足够的时间让电流检测信号调理稳定并给 ADC 采样电容充电。

图 4.15 显示了对称和不对称死区时间之间的差异。在对称死区时间中，高到低转换提前 DT/2，低到高转换延迟 DT/2。在不对称死区时间中，低到高转换延迟 DT。此图还显示在不对称死区时间插入中，PWM 中心事件延迟 T1。

dsPIC33EP：

  • 在 PWM 模块中实现对称死区时间

  • 由于对称死区时间，中心对齐周期的开始与低侧脉冲的中心对齐。

  • 不需要延迟来确保采样/转换发生在低侧脉冲的中间。

dsPIC33CK：

  • 在 PWM 模块中实现不对称死区时间

  • 由于不对称死区时间，中心对齐周期的开始略超前于低侧脉冲的中心。

  • 我们建议在 ADC 触发中添加半个死区时间的小延迟，以确保采样/转换发生在低侧脉冲的中间。

4.9.1.5. PWM 更新选项¶

对于中心对齐 PWM，有几个选项决定 PWM 占空比寄存器的更新何时实际加载到 PWM 生成器中使用。

这些选项通常包括以下内容：

  • 立即更新 ——占空比寄存器更新立即加载到 PWM 生成器中。这具有最低的额外延迟，但可能导致额外的输出转换（例如，如果占空比寄存器从较旧的较大占空比更新为较新的较小占空比，在较旧占空比已引起低到高转换之后，但在较新占空比将引起低到高转换之前）或落入 PWM 模块的已知勘误中。不建议在 MCAF 中使用立即更新。

  • 单次更新 （单次同步更新）——占空比寄存器更新在中心对齐 PWM 周期开始时加载到 PWM 生成器中。这每个 PWM 周期只为控制环路创建一次更新占空比的机会。

  • 双次更新 （双次同步更新）——占空比寄存器更新在中心对齐 PWM 周期的开始和中心都加载到 PWM 生成器中。这每个 PWM 周期为控制环路创建两次更新占空比的机会。

更新选择在电流控制环路时序中产生有效延迟。关键指标是 采样到更新延迟 \(T_{su}\)，它测量从 ADC 采样信息可用的时刻到新一组 PWM 占空比加载到 PWM 生成器的时间。单次更新和双次更新如 图 4.16所示。双次更新 PWM 允许最小延迟 \(T_{su}\) 为半个 PWM 周期。单次更新 PWM 允许最小延迟 \(T_{su}\) 为一个完整周期。实际延迟取决于控制环路执行 ADC 采样和 PWM 占空比寄存器更新之间关键代码的速度。

通常建议 MCAF 使用双次更新以减少采样到更新延迟，但某些控制方法需要其他 PWM 更新选项。 ZS/MT 在中心对齐 PWM 模式下需要单次更新。对于其他估算器， 单通道 电流测量在双沿中心对齐 PWM 模式下需要单次更新，而对于 双通道 或 三通道 电流测量，配置双次更新中心对齐 PWM 模式以减少采样到更新延迟。

注意：在 dsPIC33E 设备中，双次更新默认启用，不需要也不允许更改外设配置。对于 dsPIC33E，请检查设备勘误。某些设备的早期硅片版本实现单次更新行为而非双次更新行为。

4.9.1.6. 板级服务模块¶

MCAF 中的板级服务模块与 HAL 中的硬件访问功能（HAF）协同工作，以为 MCAF 提供板级功能。它提供两个主要的板级相关功能：板级处理程序和 PWM 自举充电例程。

4.9.1.6.1. 板级处理程序¶

板级处理程序包括配置和执行板级服务进程的接口。板级服务进程使用定时器周期性地处理板级服务。与适当的 HAL 接口配合工作，板级处理程序向用户级应用程序（如 示例应用程序。

4.9.2. 实现¶

4.9.2.1. MCC 集成¶

在 MCAF R3 之前，生成的代码未与 MCC 集成；MCAF 完全提供自己的 HAL。

4.9.2.1.1. MCAF R3¶

在 MCAF R3 中，以下项目已从 MCAF 中移除并由 MCC 负责：

  • 配置位

  • 振荡器设置

MCC 系统模块的某些方面仍存在于 MCAF 中。MCC 和 MCAF 代码都执行；MCAF 代码稍后运行并覆盖 MCC 的任何设置。以下区域由 MCC 和 MCAF 共同处理：

  • GPIO 配置

  • 中断初始化

  • CORCON 初始化

这种重叠是暂时的，这些区域计划完全转移到 MCC。

其他模块如 ADC 和 PWM 完全由 MCAF 配置，将在未来版本的 MCAF 中转移到 MCC。

4.9.2.1.2. MCAF R4¶

在 MCAF R4 中，以下项目已从 MCAF 中移除并由 MCC 负责：

  • GPIO 配置

  • 中断模块

  • CORCON 初始化

  • PWM 模块

  • ADC 模块

  • 定时器模块

  • UART 模块

  • DMA 模块

  • 看门狗模块

  • LED 模块

  • 开关模块

  • 引脚管理（部分）

MCC 处理所有外设初始化、引脚初始化、引脚管理，并且是与硬件交互的基础层。目前，由于 MCC 尚不支持 QEI，引脚管理不能完全由 MCC 单独处理。首先，MCC 系统模块配置所有外设包括设备引脚管理。然后，在 MCC 系统模块完成配置后，MCAF 引脚管理也运行以初始化 QEI 引脚。QEI 模块完全由 MCAF 处理，将在 MCC 为 16 位设备提供 QEI 支持时转移到 MCC。

大多数硬件访问操作通过 HAF 层进行，但少量对 MCC 外设层的调用直接从 MCAF 应用程序发出。未来，所有硬件访问将委托给 HAF 层。这是为了避免 MCAF 应用程序与 MCC 之间的耦合。

HAL_InterruptVectorNumberGet() 是添加到 HAF 层的函数。此函数获取中断向量号，不直接通过 MCC 执行此操作。

有关 MCAF 中 MCC 配置的更多信息，请参见 MCC 外设文档。

4.9.2.1.3. MCAF R5¶

  • 增加了对 dsPIC33CK256MP508 的支持。

  • MCAF 调用的所有外设和硬件相关功能都通过硬件访问功能层进行。

  • MCAF 需要特定的外设实例。所需实例为：PWM、ADC1、TMR1、SCCP1-TMR/TMR2、UART1 和 QEI1

  • MCC 处理大部分外设生成代码，QEI 和故障中断状态位清除除外。

4.9.2.1.4. MCAF R6¶

  • 增加了对 dsPIC33CK64MP105 和 dsPIC33CK64MC105 的支持。

  • MCC 现在处理所有外设生成代码，QEI 除外。

  • 板级服务模块重构为分为 PWM 自举充电 和 板级处理程序 部分

4.9.2.1.5. MCAF R7¶

  • 增加了对 MCC Melody 和 MCC Classic。

    • MCC Melody 仅支持 dsPIC33CK 系列设备。

    • MCC Classic 仅支持 dsPIC33EP 系列设备。

  • MCC Melody 处理所有外设生成代码，包括 QEI。使用 MCC Classic 时，MCAF 提供 QEI 代码。

  • MCAF 使用的中断优先级总结于 表 4.9。

4.9.2.1.6. MCAF R9¶

在 MCAF R9 之前，ADC 触发器硬编码为 PWM 生成器 1。从 MCAF R9 开始，用户可以通过在电路板配置文件中将任何可用的 PWM 实例映射到 Phase A 来自定义 ADC 触发源。

4.9.2.2. HAL 勘误¶

  • MCAF_BootstrapChargeStepIsr() 包含一个软启动序列，旨在缓慢打开占空比并减少栅极驱动电源负载，以充电自举电容。此序列以过低的占空比开始，可能在某些栅极驱动器中产生残缺脉冲。（DB_MC-978；适用性：MCAF R2 – R6）
