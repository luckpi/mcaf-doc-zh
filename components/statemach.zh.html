4.3. 状态机¶

电机控制状态机可以描述为分层状态机，如下方 图 4.1所示。状态以蓝色显示；名称（MCSM_xxxx）是应用程序框架代码中使用的名称。转换条件以带标签的箭头显示。

此状态机旨在从非常高的层面处理电机控制器：它不关注电机的详细信息（是否发生了堵转？是否存在过压？），而是围绕一般事件来设计，例如是否检测到故障，或者启动/停止序列是否完成。

4.3.1. 状态¶

这些状态分为以下子组：

  • 主要状态：除测试操作中使用的状态外的所有状态。

    • 正常状态：未发生故障的状态。

    • MCSM_FAULT：已发生故障。

  • 次要状态：测试操作中使用的所有状态。这些状态会导致正常状态机被忽略，同时也会忽略一些在测试模式下可能产生误报的故障检测算法。

此处的分组构成了一个分层状态机。例如：任何正常状态在检测到故障时都会转换到 MCSM_FAULT 。（传统状态机需要将到 MCSM_FAULT 的转换从 MCSM_STOPPED， MCSM_STARTING， MCSM_RUNNING， MCSM_STOPPING，和 MCSM_INIT分别显示出来。）

上电复位后的初始状态为 MCSM_RESTART。各状态简要描述如下：

状态

描述

假设条件

MCSM_RESTART

初始状态，在每次上电、退出故障状态或测试模式且当前无故障时进入。

可以执行某些运行时校准活动。

可以接受电机电流保持为零。

MCSM_STOPPING

电机控制器尝试使电机完全停止。

电机可能正在旋转。

MCSM_STOPPED

电机控制器已使电机完全停止。

电机未旋转。

MCSM_STARTING

电机控制器尝试从静止状态启动电机旋转。这可能需要专门的代码，例如在使用无传感器估计器的控制器中，或在压缩机中。

电机速度可能为零或很小。

MCSM_RUNNING

电机控制器尝试将电机控制到指定的控制目标，通常为电机速度调节。

到目前为止电机控制已成功。

MCSM_FAULT

电机控制器已识别到故障状态，在此状态下无法安全地进行正常控制活动。

电机控制器的执行器被置于 “最小影响” 状态，该状态在故障条件下被认为是可接受的：通常上桥臂晶体管关断，下桥臂晶体管关断或设置为小占空比。

这是一个“锁定”状态：进入时锁定描述故障的错误代码，并显示此代码，直到来自 CLEAR_FAULT 条件的外部干预发生。

通常没有假设。电机可能正在旋转或未旋转。电机可能已损坏，晶体管可能已损坏，电压和电流可能超出范围等。

MCSM_TEST_RESTART

测试状态，用于干净地初始化系统行为，类似于 MCSM_RESTART 但用于测试模式。

用户界面输入通常被忽略，以诊断设备的输入为准。

电机控制器正在受控条件下由了解操作的人员以非标准测试模式运行。

MCSM_TEST_DISABLE

测试状态，晶体管设置为最小影响状态。

用户界面输入通常被忽略，以诊断设备的输入为准。

在测试模式下检测到故障，或控制器被有意禁用。

MCSM_TEST_ENABLE

测试状态，晶体管已启用。控制目标由测试操作模式设定，通常与正常运行条件不同。

例如：一个或多个控制环路被禁用，某些故障检测被禁用等。

用户界面输入通常被忽略，以诊断设备的输入为准。

电机控制器正在受控条件下由了解操作的人员以非标准测试模式运行。

4.3.2. 输入条件¶

高级输入条件（如 图 4.1的状态图所示）以互斥方式使用（换言之，从给定状态出发的所有条件互斥），并可由更基本的条件定义如下：

  • FAULT：以下两项均为真：

    • operating_fault_detected 为真（见下一节）

    • 操作模式为 OM_NORMAL

  • CLEAR_FAULT：以下所有条件均为真时为真：

    • operating_fault_detected 不为真

    • UI 模块指示要清除锁定的故障。

    • 操作模式为 OM_NORMAL

  • RESTART_COMPLETE：控制器可以离开 RESTART 状态。以下所有条件均为真时为真：

    • 操作模式为 OM_NORMAL

    • operating_fault_detected 不为真

    • RESTART 状态的初始化活动已完成

  • AT_REST：控制器可以离开 RESTART 状态进入 STOPPED 状态。以下所有条件均为真时为真：

    • RESTART_COMPLETE 为真

    • 停止模式 为闭环

    • 启动例程尚未设置启动完成标志。

  • READY：控制器可以离开 RESTART 状态进入 STOPPING 状态。以下所有条件均为真时为真：

    • RESTART_COMPLETE 为真

    • AT_REST 不为真

  • RESUME：控制器可以从 STOPPING 状态进入 RUNNING 状态。以下所有条件均为真时为真：

    • RUN 为真

    • 停止模式 为闭环

    • 启动例程已设置启动完成标志。

  • RUN：电机将运行。以下所有条件均为真时为真：

    • run_requested：UI 模块指示要运行电机。

    • run_permitted：允许电机运行；如果检测到堵转条件则为假。

    • operating_fault_detected 不为真。

    • 操作模式为 OM_NORMAL

  • START_COMPLETE：以下所有条件均为真时为真：

    • RUN 为真

    • 启动例程已设置启动完成标志。

  • STOP_COMPLETE：以下所有条件均为真时为真：

    • RESUME 不为真

    • 停止完成标志已由 停止例程。

    • operating_fault_detected 不为真

    • 操作模式为 OM_NORMAL

  • TEST_DISABLE：以下所有条件均为真时为真：

    • test_fault_detected 不为真

    • 操作模式为 OM_DISABLED

  • TEST_ENABLE：以下所有条件均为真时为真：

    • test_fault_detected 不为真

    • 来自 测试框架 的 TestRestartRequired 标志未设置。

    • 操作模式为除 OM_DISABLED 或 OM_NORMAL 之外的任何其他模式

  • TEST_RESTART：以下所有条件均为真时为真：

    • test_fault_detected 不为真

    • 来自 测试框架 的 TestRestartRequired 标志已设置。

    • 操作模式为除 OM_DISABLED 或 OM_NORMAL 之外的任何其他模式

  • TEST_EXIT：如果操作模式为 OM_NORMAL，和 test_fault_detected 不为真

  • TEST_EXIT_FAULT：以下任一条件为真时为真：

    • 操作模式为 OM_NORMAL，和 operating_fault_detected 为真

    • 操作模式不为 OM_NORMAL，和 test_fault_detected 为真

  • TEST_CLEAR_FAULT：以下所有条件均为真时为真：

    • test_fault_detected 不为真

    • UI 模块指示要清除锁定的故障。

    • 操作模式不为 OM_NORMAL

  • TEST_READY：以下所有条件均为真时为真：

    • test_fault_detected 不为真

    • RESTART_COMPLETE 为真

    • 操作模式不为 OM_NORMAL

在某些方面，以优先级方式实现状态转换可能更容易理解，其实现可能如下所示：

if （operating_mode != OM_NORMAL）
{
  if （operating_mode == OM_DISABLED || test_fault_detected）
  {
    next_state = MCSM_TEST_DISABLE；
  }
  else
  {
    next_state = MCSM_TEST_ENABLE；
  }
}
/* primary states begin here... */
else if （operating_fault_detected && this_state != MCSM_FAULT）
{
  next_state = MCSM_FAULT；
}
else
{
  /* normal states */
  switch （state）
  {
    case MCSM_TEST_DISABLE：
    case MCSM_TEST_ENABLE：
      next_state = MCSM_RESTART；
      break；
    case MCSM_RESTART：
      if （ready）
      {
        next_state = MCSM_STOPPING；
      }
      break；
    case MCSM_STOPPING：
      if （stop_complete）
      {
        next_state = MCSM_STOPPED；
      }
      break；
    case MCSM_STOPPED：
      if （run）
      {
        next_state = MCSM_STARTING；
      }
      break；
    case MCSM_STARTING：
      if （!run）
      {
        next_state = MCSM_STOPPING；
      }
      else if （start_complete）
      {
        next_state = MCSM_RUNNING；
      }
      break；
    case MCSM_RUNNING：
      if （!run）
      {
        next_state = MCSM_STOPPING；
      }
      break；
    case MCSM_FAULT：
      if （clear_fault_latch）
      {
        next_state = MCSM_RESTART；
      }
      break；
    default：
      next_state = MCSM_RESTART；
  }
}

4.3.3. 状态机其他问题¶

4.3.3.1. 启动¶

在 MCSM_STARTING 状态下，使用专门的启动过程将电机从静止加速到足够高的速度，以使 无传感器估计器 提供换相信息。在此状态下，速度环路被禁用，换相角以开环方式缓慢加速，而不是使用无传感器估计器的换相角。

有关更多信息，请参见 启动 一节。

4.3.3.2. 故障检测¶

故障检测的行为略有不同，取决于系统处于测试状态还是正常操作模式。

  • test_fault_detected：在测试状态下，我们希望对允许请求的操作更加宽松，因此此标志仅在任一最严重的故障为真时才为真；这些包括硬件过流、软件过流、过压等。

  • operating_fault_detected：在正常操作模式下，我们希望更加保守，在更广泛的条件下停止操作。这包括 test_fault_detected中使用的所有故障，以及 test_fault_detected中未包含的其他故障，例如堵转重试次数超限。

    这允许检测技术在正常操作模式下使用，但在测试模式下保持禁用，以免干扰可能触发故障的测试。某些启发式检测技术属于此类，特别是当它们对电机的运行方式做出假设（例如始终在速度控制模式下、始终朝一个方向旋转、速度命令平滑变化等），或者对检测技术是否能避免误报存在不确定性时。

两种故障检测方案都是锁定的，需要外部操作来清除（例如，主要状态下按 UI 按钮，测试状态下通过诊断工具操作）。

4.3.4. 实现说明¶

函数 MCAF_SystemStateMachine_StepIsr() 是系统状态机的主入口点。此函数中使用的方法是执行以下子任务：

  • 首先执行所有状态共有的关键任务—— MCAF_MotorControllerOnAllStates()

  • 确定下一状态—— MCAF_FSM_DetermineNextState() 和 MCAF_FSM_DetermineNextStateTestMode()

  • 分派到适当的状态—— MCAF_FSM_Dispatch()

  • 最后执行所有状态共有的非关键任务—— MCAF_MotorControllerOnAllStatesLowPriority()

磁场定向控制任务在以下函数中执行：

  • MCAF_FocStepIsrFeedbackPath() ——此函数在所有状态下执行，包括反馈计算，如 Park/Clarke 变换和位置/速度估计。

  • MCAF_FocStepIsrForwardPath() ——此函数在电机控制激活的状态下执行，包括控制器和其他前向通道元素，如逆 Park/Clarke 变换和空间矢量调制。

函数 MCAF_SystemStateMachine_StepMain() 执行系统状态机的低优先级任务。目前，唯一的此类任务是为 外部接口 选择 LED 图案，以指示电机方向和状态机状态。

4.3.4.1. 堵转检测和恢复的实现说明：¶

检测到堵转将导致 run_permitted 标志为假，从而将电机从 STARTING 或 RUNNING 状态带入 STOPPING 状态。它不会改变来自 UI 的 run_requested 标志。

堵转检测/恢复需要跟踪重试次数，与现有实现一样；当重试次数超过阈值时，将产生“堵转重试次数超限”故障，并进入 FAULT 状态。

4.3.4.2. 其他实现说明¶

每个状态中的状态机函数以及转换函数，除主状态机更新函数 MCAF_FSM_Dispatch()外，不应被调用。MCAF 中使用的方法是将这些函数作为内联函数提出，以实现代码模块化和可维护性，但不是运行时模块化（在运行时将其视为一个大函数）。

STOPPING → RUNNING 转换是在 MCAF R7 中添加的，同时添加了 闭环停止。

RESTART → STOPPED 转换是在 MCAF R7 中添加的，同时添加了 AT_REST 条件的外部干预发生。 注意： 确定 AT_REST 有效性的精确条件仍在研究中，可能会在 MCAF 的未来版本中发生变化。
