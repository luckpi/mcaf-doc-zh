4.7. 外部接口¶

本节描述电机控制应用程序框架的外部接口，包括电位器、按键和 LED。

在 MCAF R6 – R9 中， 板级服务模块 实现了电位器和按键处理程序，而 示例应用程序 定义了按键按下时的行为。

为了支持所有这些系统以及在创建自定义电路板时，建议遵循以下指南。有关将 UI 元素添加到 创建自定义电路板配置 的更多信息，请参见 入门电路板定义。

  • 按键

    • 强烈建议至少使用两个按键，但不是必需的。

    • 按键输入用于手动控制输入事件功能，例如两个示例应用程序输入事件：

      • 启动/停止电机并提供从故障中手动重启。建议由主按键控制。

      • 反转电机旋转方向。建议由副按键控制。

    • 每个按键可以根据按下和释放的持续时间提供三种不同的输入：

      • 去抖：释放→按下和按下→释放转换在某个时间 T1（例如 20ms）内发生。此事件被忽略。

      • 单次按下：释放→按下和按下→释放转换在某个时间 T 内发生，其中 T1 ≤ T ≤ T2

      • 长按：释放→按下转换发生，且按下保持超过某个时间 T2（例如 2 秒）。这可用于提供不常用的输入。一旦时间 T2 已过，如果允许长按，LED 将提供某种视觉反馈以指示长按已发生。

      • 双击：两次单次按下事件在某个间隔 T3（例如 0.5 秒）内发生。这可用于提供不常用的输入。

  • LED

    • 强烈建议至少使用两个 LED，但不是必需的。

    • 每个 LED 可以根据其随时间的通电方式提供不同类型的指示：

      • 完全关闭

      • 完全点亮

      • 以高频（>100 Hz）调制以在 ½ 感知亮度下工作。（注意：由于人脑的特性，这可能不是 50% 占空比。）

      • 可感知的闪烁速率和占空比（例如 0.5 / 1 / 2Hz 闪烁速率下 5%/50%/95% 占空比）

      • 应避免 2Hz 至 55Hz 之间的闪烁速率：尽管 LED 的视觉范围相当小，但这些频率可能成为光敏性癫痫患者的触发因素。

      • 错误代码——重复且易于感知的开/关模式序列，例如 250ms 点亮时间被不同长度的熄灭间隔分隔（250ms、750ms、2250ms）；参见 错误代码 一节了解更多信息

    • 两个 LED 之间应保持一定的协调以提供简单的视觉信息（很难解读相邻的两个 LED 以不同速率闪烁）

    • 对于指示“活跃性”，应优先使用动态模式而非静态模式，以指示控制器处于活动状态且未卡在特定状态。

  • 电位器

    • 强烈建议使用电位器，但不是必需的。

    • 电位器应提供连续范围输入，例如可用于控制速度、电流或电压。

除这些通用指南外，UI 行为的选择在一定程度上是任意的。 无按键或电位器的自定义电路板 为 UI 元素数量少于推荐数量的自定义电路板提供了更多信息。

4.7.2. 已实现的行为¶

  • 启动/停止：

    • 主按键上的单次按下事件提供“启动”和“停止”输入。（如果电机已停止则请求启动电机；如果电机未停止则请求停止电机）这样做是为了与现有应用笔记 AN1078 和 AN1292 的行为保持一致。

  • 反转方向：

    • 方向标志被保持

    • 反转方向请求：

      • 如果存在第二个按键：第二个按键的单次按下事件

      • 如果不存在第二个按键：第一个按键的长按，首次在 MCAF R2 中支持。

        所需时间标称为 3 秒，由 MCAF_BOARDSERVICE_ISR_PRESCALER 在 board_service_types.h 和 BSP_EMULATED_BUTTON_DELAY_COUNT 在 hardware_access_functions_params.h以及电机控制环路频率决定。（见 勘误）

    • 如果反转方向请求在电机停止时发生，方向标志被反转但不采取其他操作。

    • 如果反转方向请求在电机运行时发生，则以下序列发生：

      • 请求停止电机

      • 电机达到停止状态

      • 方向标志反转

      • 请求启动电机

  • 从可恢复故障中手动重启（见 表 4.7）：

    • 单次按下事件，如果处于故障状态，则清除故障锁定并重启正常操作。

  • 速度控制：

    • 电位器从最小到最大调节速度（转速）的幅值。与现有应用笔记的行为相同。

4.7.3. 错误代码¶

MCAF 具有故障检测逻辑，可覆盖多种不同条件并汇总为唯一的故障代码。MCAF 将此故障代码显示为基于 1–4 次闪烁组的 LED 闪烁模式。采用此方法的原因是大于 4 次的闪烁计数难以计数。

4.7.3.1. 错误代码 LED 行为¶

4.7.3.1.1. 将错误代码转换为 LED 闪烁模式¶

给定一个表示错误代码的正（非零）整数 X，以及一个可以点亮的 LED：

  1. 将 X 转换为基数为 4 的数字序列，最低有效位在前，以最后一个非零数字结尾。

  2. 将序列中的每个值加 1。

  3. 对于每个值 k 在序列中：

    1. 重复 k 次：

      1. LED 点亮 250ms

      2. LED 熄灭 250ms

    2. 等待 500ms

  4. 等待 1500ms，然后转到步骤 3

这总是产生一个包含至少一次双/三/四闪烁的序列。

4.7.3.1.2. 将 LED 闪烁模式转换为错误代码¶

这通常不是必需的（错误代码表包含直接指示闪烁次数的列），但要转换回数字错误代码：

  1. 将闪烁次数计为 1–4 的数字序列

  2. 从序列中的每个值减去 1

  3. 将序列解释为基数为 4 的数字，最低有效位在前

4.7.4. UI 指示器中的时序和故障清除问题¶

有两个与错误代码报告间接相关的关联问题：

  • UI 指示器的时序（延迟如何实现）

  • 故障清除问题（系统返回正常操作需要发生什么）

MCAF 根据可恢复性选择了以下策略：

表 4.7 错误可恢复性¶

可恢复性

时序

故障清除

可恢复：预期由瞬时条件引起的故障：过流、超速、过压等。

我们依赖以周期性速率运行的系统状态机作为 UI 延迟的时基。

需要用户干预：按下启动/停止输入按钮。

不可恢复：发生了严重问题，如振荡器故障、堆栈溢出或看门狗超时。

我们不一定能依赖系统状态机正常运行，而是进入“偏执”模式（见下文）；使用忙等待固定数量的 CPU 周期来实现时序。

需要通过手动复位进行用户干预。

在不可恢复故障时（“偏执模式”），以下操作发生：

  • 禁用所有中断

  • 将 PWM 输出置于安全状态

  • 通过 LED 报告错误代码，依赖忙等待创建 UI 的时间延迟

4.7.5. 实现¶

4.7.5.1. 外部接口勘误¶

  • 在 TEST_DISABLE 或 TEST_ENABLE 状态下不显示 LED 模式。（DB_MC-1922；适用性：MCAF R1 – R9。）

  • MCHV-2 和 MCHV-3 的模拟按键按下时序不保证；如果主循环中有长时间运行的任务，这可能会延迟检测长按按钮所需的时间。（DB_MC-1920；适用性：MCAF R2 – R5；在 MCAF R6 中修复。）
