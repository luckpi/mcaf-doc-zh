3.3. 状态管理¶

电机控制算法需要维护大量状态变量，用于控制环和估计器（积分器和滤波器状态）、状态机（状态机的状态）、调度器（倒计时定时器）、配置参数等。

电机控制应用框架定义了若干数据结构来管理这些状态数据。两个顶层数据结构是 MCAF_SYSTEM_DATA 和 MCAF_MOTOR_DATA，分别用于存储系统级和电机级状态变量。

我们使用了一种包含三个主要方面的方法：

  • 结构 ——状态变量如何组织？

    • 将数据分组到适当的 C 结构体中

    • 遵循 Goldilocks 原则：不要太大也不要太小

  • 分配 ——状态变量如何分配？

    • 最小化独立全局变量的数量

    • 将它们放在易于查找的位置（不需要四处寻找）

  • 访问 ——函数如何访问状态变量？

    • 函数（有少数例外，如 main()、ISR 和 HAL）不直接访问全局变量

    • 基本类型直接作为参数传递

    • 结构体通过指针或 const 指针传递，并使用最小的适用结构体。

我们的目标是在系统状态设计中遵循最小知识原则；顶层模块函数可以访问整个数据结构，而底层函数只能访问适当的部分。

一个简化的示例可能有助于解释这一点。

typedef struct tagMOTOR
{
  // 电流环前向路径
  MC_DQ_T vdqCmd； // 期望的 dq 坐标系电压，电流环的直接输出
  MC_DQ_T vdq； // 期望的 dq 坐标系电压
  MC_ALPHABETA_T valphabeta； // 期望的 alphabeta 坐标系电压
  MC_ABC_T vabc； // 期望的相电压
  MC_DUTYCYCLEOUT_T pwmDutycycle； // PWM 计数值
  // 角度和速度，包括估计器
  int16_t thetaElectrical； // 电气角度
  int16_t omegaElectrical； // 电气频率
  MC_SINCOS_T sincos； // 电气角度的正弦和余弦
  ...
} MCAF_MOTOR_DATA；

顶层模块函数如下所示。注意，函数 MCAF_FocStepIsr() 确实可以访问整个 MCAF_MOTOR_DATA 结构体，但它调用的其他函数，如 MC_CalculateSineCosine_Assembly_Ram() 和 MC_TransformParkInverse_Assembly() 只能访问该结构体内的适当信息。

void MCAF_FocStepIsr（MCAF_MOTOR_DATA *pmotor）
{
  ...
  /* 从 pmotor->theta_e 计算正弦和余弦 */
  MC_CalculateSineCosine_Assembly_Ram（pmotor->thetaElectrical， &pmotor->sincos);
  /* 从正弦、余弦、Vd 和 Vq 计算 vAlpha、Vbeta */
  MC_TransformParkInverse_Assembly（&pmotor->vdq， &pmotor->sincos， &pmotor->valphabeta);
  ...
}

这使许多模块不必 #include 主系统状态，并减少了模块间依赖。整体应用行为的变化通常不会影响单个模块的行为，因此需要重新编译和测试的频率更低。

请注意，采用此方法的模块函数不“拥有”其数据。它们不分配任何全局变量，不访问任何全局变量，也不维护任何指向外部数据的永久指针。相反，数据作为参数传入。模块函数将对任何传入的数据进行操作。它们不关心操作的是来自一个电机还是另一个电机的数据，也不关心是来自测试程序的模拟数据还是来自 ADC。

因此，模块函数很容易被单元测试覆盖。我们只需创建示例输入，调用相应的函数，然后检查输出。

主应用负责为整个系统和每个电机分配程序状态变量。

这种理念的一个后果是，许多电机控制参数不能在应用中硬编码；相反，它们必须是 可配置参数。原因是我们希望使用相同的模块函数同时支持控制两个不同的电机，而每个电机可能有不同的软件参数，因此这些参数需要从代码中移除并保存在状态变量中。

3.3.1. 杂项指南¶

  • 相关的状态变量应该放在一起。如果一组变量总是同时出现和使用，那么将它们声明为结构体的成员可能是最好的选择。

  • 层次结构可以帮助并简化命名：如果有 5 个计数器，例如 counterError， counterSuccess， counterResets， counterButtonPresses，和 counterOvercurrent，这些可以合并到一个 counters 结构体中，成员不需要 counter 这个词，因为它们现在处于一个暗示它们是计数器的上下文中：

    typedef struct tagCOUNTERS
{
  uint16_t error；
  uint16_t success；
  uint16_t resets；
  uint16_t buttonPresses；
  uint16_t overcurrent；
} COUNTER_DATA；

COUNTER_DATA counters；
++counters。resets；

  • 嵌入结构体（包含其他结构体的结构体）表示所有权：被包含的结构体由包含它的结构体所拥有，并且是其固有部分。

  • 引用结构体（包含指向其他结构体的指针的结构体）表示关联和非排他性：包含的指针允许访问其他数据。
