3.2. 命名约定¶

MCAF 使用以下命名约定：

  • A 前缀 用于所有函数和类型，以降低这些函数与用户自定义代码冲突的可能性。主要前缀有

    • MC_ ——电机控制库

    • MCAF_ ——电机控制应用框架

    • HAL_ ——硬件抽象层

    • BSP_ ——板级支持包

    • MCAPI_ ——运动控制 API

  • 函数 使用前缀和 UpperCamelCase（大驼峰命名），即一个或多个单词，每个单词首字母大写（包括第一个单词）。这些通常分为两种类型：

    • 动作类： <名词短语> <动作>

      MCAF_CoastdownTimerReset()
MCAF_PllEstimatorInit()

    • 获取器类： <名词短语> <形容词短语> 或 <名词短语> <属性>

      MCAF_OperatingModeNormal()
MCAF_StartupHasCompleted()

  • 类型 以全大写字母定义，单词之间用下划线分隔：

    typedef struct
{
    int16_t d；
    int16_t q；
} MC_DQ_T；

  • 枚举 常量以全大写字母定义，单词之间用下划线分隔。同一类型中的枚举常量应具有特定于该类型的公共前缀，例如本例中的 MADC_ 前缀：

    typedef enum tagMCAF_ADC_SELECT
{
    MADC_VDC           = 0，
    MADC_POTENTIOMETER = 1
} MCAF_ADC_SELECT；

  • 变量 和结构体/联合体的 成员 以 lowerCamelCase（小驼峰命名）声明，即一个或多个单词，除第一个单词外每个单词首字母大写：

    int16_t           thetaElectrical；
int16_t           omegaElectrical；
MC_SINCOS_T       sincos；
MCAF_MOTOR_DATA *pmotor；
uint16_t          subsampleCounter；

    • 不鼓励在变量名和结构体成员中使用下划线字符。

    • 全局变量不使用前缀，因为全局变量的数量很少。此外，客户可以更改它们的名称而不会影响 MCAF，因为框架的模块不直接访问它们。

  • MCAF 使用 <stdint.h> 和 <stdbool.h>中定义的标准 C 类型，例如 int16_t， uint16_t， int32_t，以及 bool，来表示特定位宽的整数。早期应用笔记代码包含如下代码行：

    // 使用依赖于实现的类型
int count = 0；
short qVqRef；
unsigned long Startup_Ramp = 0；

// 尝试定义特定类型别名
typedef unsigned short WORD；
typedef signed int SFRAC16；
typedef unsigned char  BYTE；
typedef unsigned char  bool；
#define False 0
#define True 1

    这些后来已转换为使用 <stdint.h> 和 <stdbool.h>。

3.2.1. 附加命名指南¶

  • MCAF 有时使用具有符号性质的变量名（例如 theta 或 omega 或 iq），因为它们在电机控制理论中具有特定含义。

  • 符号名中的 camelCase 约定不应改变下标的大小写，例如我们使用 idq 和 ialphabeta 而不是 iDQ 或 iAlphaBeta。

  • 通常，变量名应以所表示量的概括描述开头，后跟更具体的限定词。这使得相关的同级变量或结构体成员在字母顺序上相邻，并允许读者在从左到右阅读时逐步缩小感兴趣的主题。因此 iMaximum， iMinimum， vMaximum， vMinimum 优于 maximumCurrent， minimumCurrent， minimumVoltage， maximumVoltage。
