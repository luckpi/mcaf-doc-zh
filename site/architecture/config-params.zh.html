3.5. 配置参数¶

MCAF 中有许多可配置参数：

  • 控制增益

  • 时间延迟

  • 斜坡速率

  • 滤波器时间常数

  • 满量程值（电流、电压、占空比等）

  • 限值（电流、电压、占空比等）

等等。速度控制环就是一个很好的例子。从代数上看，它如下所示：

(3.1)¶\[I_q = K_p \omega_{\mathrm{err}} + \int K_i \omega_{\mathrm{err}}\ dt\]

问题变成了：我们如何管理诸如 K_p 和 K_i 这样的参数，并利用定点数学？

3.5.1. 经典应用笔记¶

Microchip 的经典应用笔记（如 AN1292 和 AN1078）使用通过 C 预处理器表达的计算。例如：

代码清单 3.7 来自 AN1078 UserParms.h¶
#define DFCY 70000000 // 指令周期频率（Hz）
#define DTCY (1.0/DFCY) // 指令周期（秒）
#define DDEADTIME (unsigned int)(DEADTIMESEC*DFCY) // 死区时间（以 dTcy 为单位）
#define LOOPTIMEINSEC (1.0/PWMFREQUENCY) // PWM 周期 = 1.0 / PWMFREQUENCY
#define IRP_PERCALC (unsigned int)(SPEEDLOOPTIME/LOOPTIMEINSEC) // 每次速度计算对应的 PWM 循环数
// 从开环过渡到闭环所需的 PWM 循环
#define TRANSITION_STEPS IRP_PERCALC/4

#define SPEEDLOOPTIME (float)(1.0/SPEEDLOOPFREQ) // 速度控制周期
#define LOOPINTCY DFCY/PWMFREQUENCY // 基本循环周期（以 Tcy 为单位）
#define LOCKTIME (unsigned int)(LOCKTIMEINSEC*(1.0/LOOPTIMEINSEC))
// 从零斜坡到 MINSPEEDINRPM 所需的时间。时间以秒为单位
#define DELTA_STARTUP_RAMP (unsigned int)(MINSPEEDINRPM*POLEPAIRS*LOOPTIMEINSEC* \
 LOOPTIMEINSEC*65536*65536/(60*OPENLOOPTIMEINSEC))
// 在执行按钮例程之前必须执行的控制循环数。
#define BUTPOLLOOPCNT (unsigned int)(BUTPOLLOOPTIME/LOOPTIMEINSEC)

这种方法的优点是用于推导每个值的公式是可见的。

这种方法的缺点在于 C 预处理器的工作方式。 #define 方法纯粹是文本替换，预处理器实际上并不执行任何计算；编译器通过在编译时计算它能完成的任何计算来优化（也称为 常量折叠），但看不到预处理之前的原始代码。具体的缺点包括

  • 由于溢出、类型不匹配或不安全的计算（缺少括号来控制优先级、不检查值是否超出范围），可能导致难以理解或不可见的错误。例如：

    #define FOSC 70e6
#define SLOW_BAUDRATE 38400
#define FAST_BAUDRATE 3*SLOW_BAUDRATE
#define BRG_DIVIDER FOSC/16/FAST_BAUDRATE
U1BRG = BRG_DIVIDER - 1；

    此代码有错误；替换后的代码如下所示

    U1BRG = 70e6/16/3*SLOW_BAUDRATE - 1；

    缺少 3*SLOW_BAUDRATE

  • 无法看到中间或最终的计算值

  • 无法调试预处理器计算

  • 可以覆盖“内置”函数调用（标准数学），但无法处理更复杂的计算（例如需要循环、高级数学函数如 erf 或贝塞尔函数，或其他数值分析）

3.5.2. 电机控制应用框架¶

MCAF 方法利用了 代码生成 功能，这些功能在 motorBench® Development Suite 中。这些功能使用模板引擎；在 MCAF 固件包中，包含带有占位符表达式的参数化代码文件：

代码清单 3.8 pi_gains.h.template¶
// 电流环增益
#define KII ${INTEGRAL_GAIN_HERE } // 积分增益
#define KIP ${PROPORTIONAL_GAIN_HERE} // 比例增益

其中 ${SOME_EXPRESSION} 块中的值将被替换，最终如下所示

代码清单 3.9 pi_gains.h¶
// 电流环增益
#define KII 3.021 // 积分增益
#define KIP 7.413 // 比例增益

这提供了几个优点：

  • 可以在代码生成时使用可调试的机制进行计算

  • 中间和最终结果可以可视化

  • 可以添加浮点/工程等效值的报告

  • 几乎可以使用任何可计算的方程

上面的示例代码是浮点参数的示例；由于我们倾向于使用定点计算，固件包模板可能更像

代码清单 3.10 pi_gains.h.template¶
// 电流环增益
#define KII_Q12 <@describe_constant Q12(INTEGRAL_GAIN) />
#define KIP_Q12 <@describe_constant Q12(PROPORTIONAL_GAIN) />

使用模板宏，在注释中同时生成整数值和等效的浮点值：

代码清单 3.11 pi_gains.h¶
// 电流环增益
#define KII_Q12 12370 // 3.021 Q12
#define KIP_Q12 30364 // 7.413 Q12

然后我们可以在代码中使用定义的常量：

代码清单 3.12 pi_controller.c¶
void control_motor（motor *pmotor）
{
   ...
   int16_t current_error = pmotor->iCmd - pmotor->iMeas；
   pmotor->applied_voltage =
     ((int32_t）CURRENT_LOOP_GAIN_Q12 * current_error） >> 12；
   ...
}

这种 编译时分离 方法（将可配置参数拆分为模板生成的 C 头文件中的定义，以及在一个或多个 C 源文件中的使用）本质上是 MCAF 中使用的方法。一般来说，它具有一些重要特征：

  • 有利于优化——编译器能看到常量值，可能能够加速计算。

  • 不利于模块化——如果我们有驱动两个不同增益的电机的软件怎么办？那么我们需要 KII_Q12_MOTOR1 和 KII_Q12_MOTOR2 ，并且在 C 代码中我们需要以某种方式确定何时使用哪个。

  • 不利于开发——我们无法使用运行时诊断工具来尝试不同的增益。

  • 定义和使用点分离——这是模块化设计的必然代价。

我们通过采用稍微不同的方法来解决其中一些问题，使用 运行时分离，将配置参数存储在状态变量中：

代码清单 3.13 pi_controller.c¶
void control_motor（motor *pmotor）
{
   ...
   int16_t current_error = pmotor->iCmd - pmotor->iMeas；
   pmotor->applied_voltage =
     ((int32_t） pmotor->kp * current_error） >> pmotor->kp_shift；
   ...
}
代码清单 3.14 init_motor.c (动态生成)¶
 void init_motor_1（motor *pmotor）
 {
    pmotor->kp = 12370；    // 3.02 Q12
    pmotor->kp_shift = 12；
 }
 void init_motor_2（motor *pmotor）
 {
    pmotor->kp = 15147；    // 1.849 Q13
    pmotor->kp_shift = 13；
 }

这允许一种代码架构，使得

  • 可以使用多个电机，每个电机有不同的增益

  • 可以使用可变的移位计数，以支持为每个电机优化的动态范围。

  • 参数可以在开发和测试期间在运行时更改

运行时开销略高于每行 C 代码使用编译时固定常量而非运行时参数的情况，但对 MCAF 来说是更好的方法。

截至 MCAF 版本 1.0，编译时分离和运行时分离混合使用；我们正在迁移到在将来版本中纯粹使用运行时分离。所有与可配置参数相关的生成代码位于 parameters/xyz_params.h 文件中。

代码生成方法的一个缺点是不太容易做到“透明”；也就是说，不容易展示计算值的来源方程。我们正在努力在未来解决这个问题。
